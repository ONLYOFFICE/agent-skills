# Error codes and retries

The official table is on the [Document Builder API](https://api.onlyoffice.com/docs/docs-api/additional-api/document-builder-api.md) page.

Check `error` before `end`/`urls`: an error response is `{"error": -N}` with no `end` and no `key`, so a loop that only tests `end` reads a failure as "still generating" and spins until its own cap. Map each documented code to its own branch: `-1` unknown, `-2` generation timeout (a sync call that ran past the server's limit - move heavy jobs to `async`), `-3` document generation error (the script itself: a syntax error, an invented Office API method, bad `Argument` data), `-4` downloading the script or an opened file failed (the URL isn't reachable from the Document Server), `-6` the result database, `-8` token. A single "generation failed" string throws away the one fact that says whether to fix the script, the network, or the secret. The branch decides retries too, and the decision has to reach wherever retries actually happen: `-3` and `-8` fail identically on an identical request, so they go straight to a terminal failure; `-1`, `-4` and `-6` can be transient; `-2` means move to `async`. A job queue (BullMQ `attempts`, Celery `autoretry_for`, a retry wrapper) retries every thrown error unless the permanent ones are marked unrecoverable - labelling `-8` `retryable: false` while the queue still retries it three times is the same bug as not labelling it.
